# ТЗ: приложение для учёта строительных объектов и документов

## Контекст и цель

Нужно десктопное приложение для Windows для учёта строительных объектов (проектов), договоров и связанной с ними документации. Приложение однопользовательское, работает **полностью офлайн**, все данные хранятся локально на компьютере пользователя. Никакой авторизации, синхронизации, многопользовательского доступа не требуется.

## Технологический стек

- **Electron** — упаковка в нативное Windows-приложение (.exe с установщиком)
- **React** — интерфейс
- **Vite** — сборка и dev-сервер
- **SQLite** (через `better-sqlite3`) — локальная база данных, без сервера
- **electron-builder** — сборка установщика для Windows
- Файлы самих документов (PDF/сканы) хранятся как файлы в папке данных приложения (`%APPDATA%/<AppName>/files/`), в базе данных хранится только путь к файлу и метаданные

Работа с базой данных должна происходить в main-процессе Electron, доступ из renderer — через `contextBridge`/IPC (не давать renderer прямой доступ к файловой системе или better-sqlite3).

## Модель данных

### Объекты (objects)
Стройплощадка / проект верхнего уровня.
- `id`
- `name` — название объекта
- `comment` — свободный текстовый комментарий
- `folder_created_date` — дата создания папки объекта (редактируемая пользователем вручную, не равна `created_at`)
- `created_at` — техническая дата создания записи

### Договоры (contracts) — первичный документ
Всегда принадлежит объекту.
- `id`
- `object_id` — ссылка на объект
- `number` — номер договора
- `date`
- `amount`
- `status` — enum: `na` (N/A) / `approved` (согласован) / `pending` (ждёт согласования) / `not_sent` (не отправлен)
- `payment_status` — enum: `paid` (оплачен) / `partial` (частично оплачен) / `unpaid` (не оплачен)
- `comment` — короткий текст, 1-3 слова, для быстрой визуальной идентификации договора
- `comment_color` — enum: `pink` / `violet` (розовый или светло-фиолетовый фон метки; выбор цвета — просто визуальная маркировка, **не используется для фильтрации/группировки**)
- `created_at`

### Доп. соглашения (annexes) — первичный документ
Всегда принадлежит конкретному договору (не может существовать без договора).
- `id`
- `contract_id` — ссылка на договор
- `date`
- `amount`
- `status` — тот же enum, что у договора
- `payment_status` — тот же enum, что у договора
- `created_at`

(У доп. соглашений нет полей `number` и `comment` — эти поля есть только у договора.)

### Вторичные документы (secondary_documents)
Принадлежат либо договору напрямую, либо конкретному доп. соглашению (ровно одному родителю).
- `id`
- `parent_type` — enum: `contract` / `annex`
- `parent_id` — id договора или доп. соглашения, в зависимости от `parent_type`
- `doc_type` — enum: `act` (акт) / `invoice` (счёт) / `invoice_facture` (счёт-фактура) / `report` (отчёт) / `outgoing_letter` (исходящее письмо) / `order` (приказ) / `waybill` (накладная)
- `date`
- `amount`
- `status` — тот же enum, что у договора
- `payment_status` — тот же enum, что у договора
- `file_path` — путь к загруженному файлу в папке данных приложения
- `original_filename` — исходное имя файла при загрузке
- `created_at`

## Экраны

### 1. Список объектов (стартовый экран)
- Список/таблица всех объектов
- Сортировка по атрибутам объекта
- Кнопка добавления нового объекта
- Клик по объекту → переход в карточку объекта

### 2. Карточка объекта
**Верхний блок** — карточка объекта:
- Название объекта
- Поле комментария (свободный текст, редактируемое)
- Дата создания папки объекта (редактируемая)

**Ниже** — список договоров этого объекта в виде **аккордеона**:
- Каждый договор — свёрнутая по умолчанию строка с атрибутами: номер, дата, сумма, статус (цветная плашка), статус оплаты (цветная плашка), комментарий (цветная метка розовый/светло-фиолетовый)
- Список договоров сортируется по любому из атрибутов и по наличию типов документов
- При разворачивании договора — **две вкладки**:
  - **«Доп. соглашения»** — список доп. соглашений этого договора, тот же табличный вид (дата/сумма/статус/оплата), каждое разворачивается отдельно и показывает свои вторичные документы
  - **«Документы по договору»** — вторичные документы, привязанные к договору напрямую (не через доп. соглашение)
- Каждое доп. соглашение при разворачивании показывает таблицу своих вторичных документов (акты/счета/счета-фактуры и т.д.), с сортировкой по атрибутам и фильтром по типу документа

**Визуальные принципы для иерархии:**
- Отступ + тонкая вертикальная линия слева, показывающая связь родитель→потомок (как в файловом дереве)
- Иконка перед строкой обозначает тип документа
- Цветные плашки статуса и статуса оплаты считываются мгновенно без чтения текста
- Всё свёрнуто по умолчанию, кроме списка договоров верхнего уровня

### 3. Глобальный реестр документов
Отдельный экран — плоская таблица всех документов (первичных и вторичных) по всем объектам сразу.

Колонки: Объект | Договор | Доп. соглашение (если есть) | Тип документа | Категория (первичный/вторичный) | Дата | Сумма | Статус | Статус оплаты

- Сортировка по любой колонке
- Мультифильтр (например: показать все «не оплачено» по всем объектам разом)
- Клик по строке → переход в контекст (карточка соответствующего объекта/договора/ДС)

### 4. Добавление документа (модальное окно через иконку +)
Пошаговый мастер:
1. Загрузка файла
2. Выбор категории документа: первичный (договор / доп. соглашение) или вторичный (акт/счёт/счф/отчёт/исходящее письмо/приказ/накладная)
3. Привязка: объект → договор → (доп. соглашение, если применимо и если документ вторичный)
4. Ввод атрибутов, соответствующих выбранному типу (поле «номер» и «комментарий» показываются только для договора)

## Дизайн-система

Стиль — деловой реестр/ведомость документов, а не типовая SaaS-панель со скруглёнными карточками и тенями.

**Цвет:**
- Фон: тёплый светлый нейтральный (`#EDEEE9`)
- Поверхность карточек: `#FFFFFF`
- Основной текст: тёмно-синий графит (`#1B2430`)
- Акцент (кнопки, активные состояния): строительный оранжевый (`#C4501C`)
- Разделители/структурные линии: приглушённый серо-зелёный (`#8A9A93`)

**Статус согласования:**
- N/A: серый текст `#6B7280` на фоне `#F1F2F4`
- Согласован: зелёный текст `#2F855A` на фоне `#E6F4EC`
- Ждёт согласования: янтарный текст `#B7791F` на фоне `#FDF3DC`
- Не отправлен: серо-синий текст `#64748B` на фоне `#EEF0F2`

**Статус оплаты:**
- Оплачен: зелёный (та же пара, что «согласован»)
- Частично оплачен: янтарный (та же пара, что «ждёт согласования»)
- Не оплачен: красный текст `#C53030` на фоне `#FBE7E7`

**Метка-комментарий договора:**
- Розовый: текст `#AD1457` на фоне `#FCE4EC`
- Светло-фиолетовый: текст `#6B3FA0` на фоне `#EDE3F5`
- Пользователь выбирает один из двух цветов вручную при создании/редактировании договора

**Типографика:**
- Интерфейсный текст: Inter
- Числовые данные (даты, суммы) — моноширинный шрифт (IBM Plex Mono), чтобы колонки чисел визуально выравнивались, как в бухгалтерской ведомости

**Layout:**
- Левое выравнивание
- Тонкие линии-разделители между строками вместо теней и карточек с тенью
- Минимальные скругления углов (2–4px), не полностью скруглённые элементы
- Цвет используется строго функционально (статусы, метка-комментарий) — никаких декоративных градиентов

## Порядок разработки

Собирать пошагово, экран за экраном, проверяя каждый шаг перед переходом к следующему:
1. Каркас проекта: Electron + Vite + React, настройка SQLite и IPC-моста между main и renderer процессами
2. Схема базы данных и слой доступа к данным (CRUD для объектов, договоров, доп. соглашений, вторичных документов)
3. Экран 1: список объектов + добавление объекта
4. Экран 2: карточка объекта с аккордеоном договоров/доп. соглашений/вторичных документов
5. Модальное окно добавления документа
6. Экран 3: глобальный реестр документов с фильтрами
7. Сборка установщика для Windows через electron-builder
